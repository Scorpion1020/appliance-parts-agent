# 系统架构说明

本文描述当前版本（纯 Python LangGraph + FastAPI 后端 + Next.js 15 前端）的完整架构与关键工程设计。

## 1. 整体分层

1. **前端展示与会话代理层（Next.js 15 + React 19 + TypeScript）**
   * 负责浏览器交互、SSE 流式进度渲染、结构化商品/证据/确认卡片展示、点赞点踩反馈采集及侧边栏会话指标展示。
   * 服务端路由（`/api/chat/stream`、`/api/conversation`、`/api/feedback`、`/api/metrics`）统一管理会话 Cookie、请求校验与中文文案映射，浏览器不直接访问 Python 后端。
2. **智能体编排与工具执行层（FastAPI + Python LangGraph）**
   * `decide` 节点：携带最近 4 轮历史、结构化记忆（当前型号、设备类型、按序候选列表、已选配件）与已执行结果，通过原生多工具调用（`tool_choice="required"`）决策下一步工具。
   * `execute` 节点：严格校验工具白名单、参数格式与编号来源（禁止模型凭空编造配件号或型号），执行只读工具并写回状态。
   * `summary` 节点：在确定性结果组装完成后，基于已核验 JSON 生成受控中文摘要（`groundedSummary`），不覆写价格、库存与适配结论。
3. **数据与持久化层（SQLite + 结构化索引）**
   * SQLite 保存会话记忆、最近 40 轮对话、请求执行租约、幂等购物车操作记录与 `turn_feedback` 用户反馈表。
   * 商品目录（20 SKU）与演示安装/型号明细由统一脚本 `exportShoppingCatalog.ts` 同步生成；知识库（15 份厂家文档 / 30 片段）通过确定性构建脚本生成带版本指纹的索引。

## 2. 安全与确定性护栏

* **读写分离（Human-in-the-Loop）**：模型只能调用 7 类只读/建议工具，绝对禁止直接写购物车；加购必须经前端确认按钮触发独立写入通道。
* **上下文绑定与防过期**：待确认建议绑定生成时的 `modelNumber` 与 `applianceType`；型号切换、价格变化或后续出现负向/未知适配证据时返回 `409` 阻止确认。
* **防死循环与防注入**：单轮上限 6 次模型调用 / 55 秒总预算；重复工具指纹拦截；工具输出标记为不可信数据；未知写入工具调用在 `execute` 阶段直接拒绝。
* **证据分层**：维护知识摘要不可作为型号适配证明；精确适配仅采信有效期 90 天内的审核快照或实时来源，证据冲突时返回“未知”。
